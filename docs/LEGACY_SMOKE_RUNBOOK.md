# Budgeted duplex speech post-training

**Historical instructions, preserved for audit. Use [the current research runbook](RESEARCH_RUNBOOK.md). Statements below describe earlier stages and are superseded by [the executed audit](SMOKE_AUDIT.md).**

A working experiment repository for English appointment corrections and versioned calendar facts, built around pinned NVIDIA PersonaPlex/Moshi source. It contains checked scenario/teacher pipelines, real CPU speech rendering and WAV import, causal Mimi caching, selective temporal LoRA SFT, matched streaming replay, cached-ASR scoring, atomic checkpoints/export, offline W&B, and persistent Modal reservation control.

**No paid GPU or teacher/TTS session was launched. No real PersonaPlex adapter, improvement, audio-quality score or public benchmark result is claimed.** The CPU fixture is artificial. See [STATUS.md](STATUS.md) for actual commands/results and remaining gates; [compatibility](docs/COMPATIBILITY.md), [data formats](docs/DATA.md), [security](docs/SECURITY.md), and [license notices](THIRD_PARTY_NOTICES.md) describe the boundaries.

## Local setup and verified CPU path

Use a repository checkout: the audited runtime is in `vendor/personaplex`, and must not compete with another installed `moshi`. Python 3.11 or 3.12 is supported; Linux is required for the native `sphn` codec/runtime extra. `uv.lock` pins the environment. The actual Modal CLI is 1.6.3 and W&B is 0.31.0. Upstream's older dependency constraints are deliberately not installed as a second package.

Windows owned-code checks:

```powershell
uv sync --locked --group dev
.venv\Scripts\duplex.exe doctor
.venv\Scripts\duplex.exe fixture --out runs/cpu-fixture
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check src tests scripts modal_app.py
.venv\Scripts\mypy.exe src/duplex
.venv\Scripts\python.exe scripts/security_check.py
.venv\Scripts\python.exe scripts/secret_scan.py
.venv\Scripts\python.exe -m pip_audit --local
```

For native CPU tests and real eSpeak rendering, use WSL/Linux. Install the OS `espeak-ng` and `libsndfile1` packages through your distribution package manager. The supplied Linux setup uses hashed official **CPU Torch wheels**, takes non-CUDA dependencies from the same project lock, and avoids installing NVIDIA CUDA packages just to run tests:

```bash
bash scripts/setup_cpu_linux.sh
uv export --locked --only-group dev --no-emit-project --output-file /tmp/duplex-dev.txt
uv pip install --python .venv-linux/bin/python -r /tmp/duplex-dev.txt
source .venv-linux/bin/activate
python -m pytest -q -p no:cacheprovider
python scripts/verify_local_audio.py
python scripts/verify_tracking.py
duplex fixture --out runs/cpu-fixture
```

The default tiny fixture generates 24 scenarios, renders tone plumbing, runs two tiny CPU optimizer steps, verifies frozen weights/gradients, saves and reloads a safe adapter/checkpoint, and writes `fixture-result.json`. Tone never enters real encoding/training/evaluation, and fixture adapters cannot use the publishable speech export CLI. Native CPU tests additionally exercise actual upstream LMModel/LMGen with tiny random parameters; they do not load the 7B checkpoint.

## Credentials, rights, and CPU preparation

Accept the gated [model terms](https://huggingface.co/nvidia/personaplex-7b-v1) yourself before downloading. Use a least-privilege HF read token, set through your environment or a Modal Secret; never paste a token into a command, YAML, image, checkpoint or shell history. `.env.example` is documentation; the program does not automatically source `.env`. Review all model/data/voice terms before any release. No full OpenYap download is required or implemented.

Build the candidate pool offline:

```bash
duplex scenarios --config configs/pilot.yaml --out data/candidates.jsonl
duplex validate --data data/candidates.jsonl
duplex select --data data/candidates.jsonl --split train-dev --groups 6 --out data/targets-input.jsonl
```

`select` retains whole counterfactual groups. Select train and dev separately if you need exact balanced pilot counts. Reserve test data in a separate manifest; never use it to select targets, hyperparameters or checkpoints. Import checked teacher JSONL, or configure an explicit separately budgeted teacher:

```bash
duplex targets --data data/targets-input.jsonl --import-jsonl data/teacher-import.jsonl --out data/targets.jsonl
# Optional paid teacher: first EDIT a local copy of configs/teacher.example.yaml,
# choose model/current provider rates and a separate API budget; set TEACHER_API_KEY.
duplex targets --data data/targets-input.jsonl --teacher-config data/teacher.yaml --cache cache/teacher --out data/targets.jsonl
```

For entirely offline plumbing/control targets, use `--reference-fixture` instead. This uses the deterministic simulator verbalizer and is not stronger-teacher transfer. Test references are evaluation annotations; actual test responses must still be generated by the model from speech.

## Modal shell workflow

The required interface is `modal shell`, with a small managed image and CPU/GPU specifications. No Docker daemon, manually created Sandbox, container exec, deploy, public server or tunnel is needed. Native Windows `modal shell` is rejected by SDK 1.6.3: launch from WSL/Linux.

The image installs `requirements-modal.txt`, a hashed export of `uv.lock`, then installs owned code with dependency resolution/build isolation disabled. This avoids a cloud-only `uv sync --locked` re-resolution failure while retaining exact dependency versions and hashes. After intentional lock changes, regenerate with `uv export --locked --extra gpu --no-dev --no-emit-project --output-file requirements-modal.txt`. `python scripts/check_modal_lock.py` verifies the export and the Python 3.11.12/uv 0.8.10 install plan locally without allocating Modal resources; CI runs this check too.

Shell persistence uses filesystem flushing rather than `Volume.commit()`: that RPC rejects calls from the managed shell process. `python -m duplex.volume_commit` now runs bounded `sync` on the three mountpoints. On v2 Volumes this triggers an explicit commit; v1 Volumes rely additionally on Modal's background and final-shutdown commits. After exiting, verify files using `modal volume ls duplex-data /encoded` and `modal volume ls duplex-cache /assets` before allocating a GPU. Checkpoints likewise require a fresh-reader persistence check. Existing v1 Volumes are preserved; no migration or recreation is performed. See [Modal's persistence documentation](https://modal.com/docs/guide/volumes#background-commits).

Verified CLI syntax comes from the installed SDK/help and [Modal shell docs](https://modal.com/docs/cli/latest/shell). These **command shapes** were checked locally; no remote image build, download, shell lifecycle or volume round trip was executed. `modal_app.py` imports locally without allocating resources.

Create the volumes and an HF-read secret once. `modal secret create duplex-hf-read --from-dotenv ...` is intentionally not prescribed: use the Modal dashboard secret editor to avoid accidental shell exposure. The CPU spec expects the secret name `duplex-hf-read` containing only `HF_TOKEN`.

```bash
modal volume create duplex-cache
modal volume create duplex-data
modal volume create duplex-runs
modal shell modal_app.py::cpu_prepare
```

Inside that CPU shell:

```bash
cd /opt/duplex
source .venv/bin/activate
duplex prepare-assets --assets /cache/assets
# Copy selected manifests/imported targets/licensed audio to /data first using
# modal volume put from your local machine (see modal volume put --help).
duplex render --data /data/targets.jsonl --root /data/pilot --assets /cache/assets --backend espeak
duplex encode --data /data/pilot/rendered.jsonl --root /data/pilot --assets /cache/assets --out /data/encoded --cache /cache/mimi
# Optional: add the SAME licensed --voice WAV to encode/profile/replay commands.
# Optional, only if licensed isolated ordinary clips/timings exist:
duplex replay-encode --manifest /data/replay.jsonl --source-root /data/replay --assets /cache/assets --out /data/encoded --cache /cache/mimi --max-audio-s 180
python -m duplex.volume_commit
exit
```

Build dependencies/download the base/codec/tokenizer on CPU first. Prepare only a small selected subset, initially 1-3 train groups plus 1-3 dev groups and 1-3 untouched test groups. The 400-row candidate pool is **not** an instruction to synthesize/encode everything. Real rendering requires the pinned tokenizer; if unavailable, it fails with an actionable error. Natural licensed WAVs plus checked timings can use `audio-import` instead. Keep test audio separate and identical across both model runs. After profiling, choose total duration/steps from measured throughput and remaining reservation; reject any plan that cannot reserve matched evaluation and checkpoint time.

The raw syntax `modal shell modal_app.py::gpu_shell` is valid but bypasses the local budget wrapper. **Recommended GPU launch, only after separate paid execution authorization:**

```bash
duplex shell --config configs/train.yaml --ledger runs/budget.json --seconds 3300
```

The launcher atomically acquires a project lease in Modal Dict, reserves time before allocation, invokes the standard `modal shell modal_app.py::gpu_shell --cmd ...`, and starts a remote process-group watchdog. CPU shell and image-build costs count against the explicit non-GPU reserve. The GPU spec mounts no HF/teacher/upload/W&B secrets; all model files must already be cached. Use the same Modal workspace and persistent local ledger on resume. No automatic lease expiry/reset bypasses an unresolved reservation.

**Important SDK behavior:** 1.6.3 hardcodes shell timeout to 3600 seconds and creates its managed shell backend from the referenced function spec; the Function's timeout/max-containers are not a shell spending cap. The wrapper uses <=3300s reservations, includes loading/idle/failures, sends TERM with 180s inside the reservation for saving, bounds volume-commit workers to 30s, then kills leftover child jobs if necessary. Multiple short shells are required for a four-hour aggregate experiment. The one-hour platform fallback, client disconnect behavior and remote commits have not been empirically verified. No perfect spending cap is promised.

## Measured smoke, one training run, and matched replay

Inside a budgeted GPU shell:

```bash
cd /opt/duplex
source .venv/bin/activate
duplex doctor
duplex profile --config configs/train.yaml --assets /cache/assets --encoded /data/encoded --data /data/pilot/rendered.jsonl --root /data/pilot --run /runs/pilot --ledger /runs/budget.json
duplex plan --config configs/train.yaml --profile /runs/pilot/profile.json --remaining-s 2400
duplex train --config configs/train.yaml --assets /cache/assets --encoded /data/encoded --run /runs/pilot --profile /runs/pilot/profile.json --ledger /runs/budget.json
python -m duplex.volume_commit
exit
```

`profile` is the real-checkpoint smoke test, not a simulated success: actual weights, forward/backward, optimizer, frozen checks, adapter reload, short audible generation and measured wall/memory/RTF. Use the **same full training config** for profile/train; `configs/smoke.yaml` is a standalone shorter smoke variant, whose profile cannot authorize a different training config. Missing real assets/CUDA or a non-single-A100-80GB configuration fails. The plan uses measured throughput, fixed evaluation/checkpoint reserve minima, remaining wall time and at most 500 steps. No sweeps or automatic OOM retries occur. After an OOM, stop; record at most one recovery with `budget-oom-recovery`, shorten **complete** sessions, and reprofile. Never silently change GPU/microbatch, truncate away response targets or reset the budget.

Generation budgeting now measures a **complete training conversation**, including prompt setup once per example, plus loading both evaluation models. The old 20-frame/1.6-second smoke rollout mixed prompt overhead into an extrapolated RTF and could incorrectly block every 55-minute shell. If you already have a successful old smoke profile, run the same `duplex profile ...` command with `--generation-only`; it reuses the saved smoke adapter and compatibility evidence, preserves the old profile as `profile.before-generation-calibration.json`, and measures full-session generation. Default evaluation count is 12 examples per model, declared through `--eval-examples` in groups of four. Training still reserves at least 1800s for evaluation and 180s for checkpointing, and refuses if the complete-session measurement does not fit. No budget ceiling is increased.

Generate baseline/adapted speech through exactly the same runtime, selected held-out WAVs, facts, prompt, voice, greedy decoding and seeds. Each CLI command is a normal process in the shell; append `exit` when a noninteractive stage is finished so the GPU is not left idle. Baseline generation can be done before training in its own bounded shell. The checkpoint should be the dev-selected `best.json` pointer, not a test-chosen result.

```bash
duplex replay --assets /cache/assets --data /data/test/rendered.jsonl --root /data/test --out /runs/eval-base --limit 12
duplex replay --assets /cache/assets --data /data/test/rendered.jsonl --root /data/test --out /runs/eval-adapted --adapter /runs/pilot/checkpoints/step-000025 --limit 12
# One-example local replay/demo uses the same command with --limit 1.
# Supply cached, hash-matched local ASR JSONL for actual audible scoring:
duplex evaluate --data /data/test/rendered.jsonl --root /data/test --base /runs/eval-base --adapted /runs/eval-adapted --base-asr /data/base-asr.jsonl --adapted-asr /data/adapted-asr.jsonl --out /runs/results
python -m duplex.volume_commit
exit
```

The test manifest must contain exactly the examples generated for both runs (e.g. 12 examples, not all 44). Results include machine-readable JSON and a short Markdown report with grouped paired bootstrap intervals, clean/overlap results, latency, hallucinations, unchanged constraints, RTF/silence/truncation and ASR uncertainty. Omitting both ASR arguments produces an explicit internal-text proxy. It must not be described as an audible speech result. Listen to generated WAVs, especially ambiguous cases. Do not claim improved audio quality from text accuracy.

An optional `benchmark-replay --inputs ... --limit 2` bridges licensed v1/v1.5 `user_interruption` `input.wav` files to local `output.wav` at pinned Full-Duplex-Bench commit. It uses this system's appointment prompt, not the benchmark's official teacher prompt; no official scorer/VAD/Judge is executed and no public benchmark score is claimed. Ordinary replay can also be replayed through this WAV bridge as listening/RTF regression material, with the prompt/subset modifications clearly recorded. Keep this optional work inside reserved time.

## Checkpoint recovery, release and shutdown

Complete checkpoints have checksummed `complete.json`, safetensors adapter, restricted local optimizer/RNG state, sampler position, configuration, exact revisions/target names/data fingerprints and ledger reference. Half-written directories never count as complete. The last two completed checkpoints and best dev checkpoint are retained. Constant LR is intentional. Save/resume cannot claim bitwise CUDA determinism.

After interruption, confirm the actual app/container stopped in Modal; `exit`/client termination alone is insufficient evidence. Inspect the app ID printed by Modal, use `modal app stop APP_ID` if needed, and check the dashboard for zero running GPU allocation. Do not use another app's ID. Reconcile both persistent ledgers and release the atomic project lease from your local machine:

```bash
duplex budget-status --ledger runs/budget.json
duplex budget-reconcile --config configs/train.yaml --ledger runs/budget.json --session SESSION_ID --confirmed-stopped
```

If a crash left `gpu-lease.json` on the runs Volume, inspect it and confirm the corresponding shell stopped before `modal volume rm duplex-runs gpu-lease.json`. If startup failed before the remote ledger was written, inspect local/cloud state; use `budget-close --ledger ... --session ... --confirmed-stopped --release-cloud-lease` only after confirming no remote allocation exists. No reservations are silently reset. Modal Dict is a workspace lease; other workspaces or bypassing the wrapper are outside its enforcement.

Start a fresh budgeted shell, check the last checkpoint completion marker, and resume with the same assets/data/config:

```bash
duplex train --config configs/train.yaml --assets /cache/assets --encoded /data/encoded --run /runs/pilot --profile /runs/pilot/profile.json --ledger /runs/budget.json --resume /runs/pilot/checkpoints/step-000025
```

If local metrics are ahead of a surviving checkpoint, resume into a fresh linked run directory to avoid nonmonotonic optimizer-step logging. Data/config/revision mismatches reject. A killed save/commit preserves at most the last fully completed **persisted** checkpoint; a fresh-shell round trip remains a required real-session check.

Export an actual trained checkpoint after evaluation:

```bash
duplex export --checkpoint /runs/pilot/checkpoints/step-000025 --out /runs/release
modal volume get duplex-runs release ./release
# OPTIONAL separate explicit release action after rights review, with an upload-scoped token:
duplex upload --release ./release --repo-id YOUR_ORG/YOUR_PRIVATE_REPO --terms-reviewed
```

Export includes safetensors, exact architecture/LoRA config and modules, revisions, checksums, model card/loading example and license notices. It never automatically merges, publishes or includes raw audio, tokens, optimizer state or dataset files. `upload` selects only the audited release allowlist; create/configure the intended private destination yourself. No weights have been published here.

## Budget and limitations

User-reported remaining balance: $24.51. Initial ceiling: $18. Target: four aggregate single-GPU hours; hard configured maximum five. Prices checked 2026-10-31 at [Modal pricing](https://modal.com/pricing): A100 80GB $0.000694/s; physical CPU core $0.0000131/s; RAM $0.00000222/GiB/s; volume storage $0.09/GiB/month; egress $0.04/GiB, before plan allowances. The inspected shell backend motivates a conservative **3x CPU/RAM** rate with 2 physical cores/32 GiB: $3.548592/hour combined before 15% safety margin. Four hours + margin + $1.50 non-GPU reserve is about **$17.82 estimated**. Four 3300s reservations total 3.67 hours and about **$16.46** including that reserve. Actual CPU/RAM use, regional premiums, storage retention, build work, egress and platform billing may differ. Recheck prices/account balance before authorization; do not assume plan free tiers.

The $1.50 reserve assumes short CPU prep, ~40GiB retained for roughly one day, and bounded egress. Long retention or larger downloads need a new explicitly reviewed estimate within the same ceiling. Teacher/TTS API costs are separate; default teacher budget is zero and local eSpeak has no API fee. No Modal/teacher/TTS charges were incurred by these local checks. The ledger tracks conservative reservations, completed stages, one OOM recovery allowance and elapsed time across sessions; it does not read an exact Modal invoice.

Unverified gates: actual gated checkpoint/codec/tokenizer behavior, single-A100 memory/throughput, managed image build, Modal disconnect/watchdog/commit persistence, held-out speech improvement and redistribution clearance. If the real smoke cannot fit/finish with matched evaluation time, stop and report its diagnostics; this repo does not quietly substitute another model or GPU. Optional second-pass mining/RL/online judges are disabled. Honest neutral or worse results are valid experiment outcomes.
